> 版本：v2.1

## 1. 文档信息

### 1.1 产品名称

**磐石交易AI**

### 1.2 文档目的

本文档定义磐石交易AI的产品需求。产品定位为**策略化预测分析助手 + 策略商店**：

- 用户可以在策略商店中浏览不同策略；
- 每个策略通过展示**最近三个月的实际运行表现**，帮助用户判断是否值得购买；
- 购买后，用户通过自然语言与系统交互，使用已购策略对指定标的进行预测分析。

### 1.3 关键变更点

| 旧定位 | 新定位 |
|---|---|
| 单一分析工具 | 策略商店 + 策略化分析工具 |
| 策略由系统默认提供 | 策略可购买、订阅 |
| 策略效果不透明 | 每个策略展示最近三个月表现 |
| 用户被动使用策略 | 用户基于最近表现主动选择并购买策略 |
| 无商业模式 | 策略付费（单次购买 / 订阅） |

## 2. 产品定位

### 2.1 一句话定位

> 磐石交易AI 是一个**策略商店 + 策略化预测分析助手**。用户可以在商店中查看每个策略最近三个月的表现，购买或订阅后，通过自然语言使用策略对指定标的进行预测分析。

### 2.2 产品边界

- **不是投研平台**：不提供深度投研工具、自定义指标编辑、策略社区。
- **不是交易执行系统**：当前版本不连接实盘，不执行下单。
- **不是通用聊天机器人**：所有对话围绕"已购策略 + 指定标的 + 预测分析"展开。
- **不是模型选择器**：用户不选择、不配置底层大模型或多模态模型。
- **不是免费策略集合**：策略分为免费策略和付费策略，付费策略需要购买或订阅后才能使用。

### 2.3 核心场景

1. **浏览策略商店**：用户查看不同策略最近三个月的表现，选择想购买的策略。
2. **查看策略近期表现**：用户看策略最近三个月的信号记录、涨跌情况、整体表现。
3. **购买策略**：用户单次购买或订阅某策略，解锁完整使用权限。
4. **使用策略分析**：用户用已购策略分析指定标的，获得预测结论。
5. **对比策略**：用户对同一标的使用多个已购策略，比较不同策略的结论。

## 3. 目标用户

### 3.1 主要用户

| 用户类型 | 特征 | 需求 |
|---|---|---|
| 散户投资者 | 有基本交易经验，想使用成熟策略辅助决策 | 看到策略最近表现，购买后可快速获得分析结论 |
| 机构投资者研究员/交易员 | 需要快速验证和跟踪策略信号 | 通过最近表现评估策略是否适合当前市场 |
| 策略爱好者 | 想尝试不同策略视角 | 在策略商店中比较、选择多种策略 |

### 3.2 用户画像

- **小王，32岁，期货散户**：没有精力自己研究，希望在策略商店选一个最近三个月表现稳定的策略，每天晚上花5分钟看信号。
- **李经理，40岁，私募研究员**：需要把策略信号和团队判断结合，通过最近三个月表现评估策略是否适应当前市场。

## 4. 价值主张

### 4.1 用户价值

- **降低选策略门槛**：通过查看策略最近三个月表现，直观比较不同策略。
- **降低分析门槛**：购买策略后，不需要懂技术指标、不需要下载数据。
- **策略效果透明**：最近三个月的信号和结果全部可查看。
- **可解释**：每个结论都有依据、数据来源和触发条件。
- **交互自然**：像聊天一样提问、补充信息、追问结果。

### 4.2 平台价值

- 构建"策略即商品"的商业模式。
- 策略开发者可以变现，平台获得分成（未来）。
- 所有分析可审计、可复现，建立用户信任。
- 数据和模型解耦，便于独立升级和扩展策略库。

## 5. 产品原则

### 5.1 策略效果透明

- 每个策略必须展示**最近三个月的表现**。
- 展示内容必须简单直观，避免专业术语。
- 必须说明时间范围和计算方式。

### 5.2 购买后可使用

- 用户购买或订阅策略后，可以在会话中随时使用。
- 未购买的策略只能查看详情和最近三个月表现，不能用于实际分析。
- 订阅到期后，策略自动降级为只读（可查看历史分析，不可新建分析）。

### 5.3 对话即界面

- 用户从首页开始即可直接输入自然语言。
- 策略选择、标的指定、信息补充、结果追问都在对话中完成。

### 5.4 策略驱动信息抽取

- 系统需要向用户询问什么信息，由**当前策略的信息依赖声明**决定。
- 不同策略需要的信息不同，系统只问当前策略真正需要的信息。
- 能自动获取的数据绝不问用户。

### 5.5 数据来自系统能力

- 量价数据、事件因子、宏观数据等由系统内部数据源提供。
- 用户不需要上传 Excel、连接行情终端或填写历史数据。
- 截图/文件仅作为辅助证据。

### 5.6 结论可解释

- 每个结论必须说明：策略名称、版本、依据、数据来源、置信度、触发条件。
- 用户可以随时追问"为什么""依据是什么""什么条件下会变化"。

### 5.7 信息不足不硬跑

- 如果当前策略运行所必需的信息无法从系统和用户沟通中获得，系统**明确拒绝运行策略**。
- 系统会告诉用户：缺少什么信息、为什么需要、如何补充。

### 5.8 模型不可见

- 用户不选择大模型、不配置模型参数。
- 底层多模态模型、语言模型、数据模型都是系统内部能力。

## 6. 核心功能

### 6.1 策略商店

#### 6.1.1 策略列表

- 展示所有可用策略（免费 + 付费）。
- 每个策略卡片展示：
  - 策略名称和版本
  - 策略标签（趋势、反转、事件驱动等）
  - 适用市场/周期
  - **最近三个月涨跌幅度**
  - **最近三个月信号胜率**
  - 价格（免费 / 单次购买 / 订阅）
- 支持按标签、市场、周期、表现、价格筛选和排序。

#### 6.1.2 策略详情页

- 策略详细介绍。
- **最近三个月表现**：收益曲线、信号记录、涨跌次数。
- 适用标的和周期。
- 策略逻辑简介（不暴露核心参数）。
- 用户评价（后续）。
- 价格与购买选项。

### 6.2 策略购买与订阅

- **单次购买**：一次性付费，永久使用当前版本（大版本升级可能需要补差价）。
- **订阅制**：按月/按年付费，订阅期内可使用策略及更新版本。
- **免费策略**：无需购买，可直接使用。
- 购买流程：
  1. 用户在策略详情页点击购买/订阅。
  2. 系统展示价格、权益、风险提示。
  3. 用户确认并支付。
  4. 系统授权策略到用户账号。
  5. 用户可在策略列表和对话中使用该策略。

### 6.3 用户策略库

- 用户已购买/免费的策略集中展示在"我的策略"。
- 显示每个策略的授权状态：永久、订阅中、已过期。
- 支持按状态筛选。
- 支持续费订阅。

### 6.4 自然语言交互

- 用户可以用自然语言发起分析请求。
- 支持多轮对话澄清、补充、追问。
- 支持上传图片、PDF、截图等附件作为辅助证据。

### 6.5 策略选择

- 系统提供策略列表，用户可以选择当前要使用的策略。
- 只能选择已购买或免费的策略。
- 未购买策略在对话中提示去商店查看。
- 每个策略展示：名称、版本、简介、适用标的、适用周期、所需信息、输出示例。
- 系统支持默认策略，未明确选择时使用默认免费策略。

### 6.6 标的选择与识别

- 用户可以通过自然语言指定标的，例如"分析一下螺纹钢"。
- 系统从用户输入、附件、上下文中识别标的。
- 存在歧义时，系统向用户确认。

### 6.7 信息抽取

- 系统从用户对话和附件中抽取当前策略所需信息。
- 抽取的信息分为两类：
  - **用户私有信息**：如持仓方向、持仓数量、成本、止损、风险承受能力等。
  - **辅助确认信息**：如用户关注的周期、关键价位、事件等。
- 系统会展示抽取结果并请用户确认。

### 6.8 策略运行

- 系统基于策略需求，自动获取所需数据（量价、事件因子等）。
- 运行策略模型，生成预测分析结论。
- 策略运行需要满足最低信息门槛，否则不运行。

### 6.9 结果呈现

- **自然语言总结**：用通俗易懂的语言说明结论。
- **可视化展示**：K线、指标、信号标记、关键价位等。
- **策略链路**：展示策略运行的关键步骤和状态。
- **审计信息**：策略版本、数据时间、数据来源、置信度。

### 6.10 追问与推演

- 用户可以追问结论依据、条件变化、情景推演。
- 系统区分解释型追问和事实修正型追问。
- 事实修正会生成新的分析版本。

### 6.11 策略扩展

- 新策略通过标准接口接入，无需修改核心系统。
- 策略可以独立开发、测试、上线、下线、回滚。

## 7. 系统架构

### 7.1 逻辑架构

```text
用户
  ↓
Next.js Web（策略商店 / 对话界面 / 可视化 / 支付页）
  ↓
FastAPI（会话管理 / 意图识别 / 信息抽取 / 策略编排 / 授权检查）
  ↓
├─ 策略商店服务（策略列表、详情、定价、购买记录）
├─ 授权服务（用户策略权限校验）
├─ 策略表现跟踪服务（计算并记录策略最近三个月表现）
├─ 信息抽取层（从对话/附件中提取策略所需信息）
├─ 数据能力层（行情数据、事件因子、指标计算）
├─ 策略注册表与策略运行时
├─ 风险与约束检查
└─ 结果渲染与自然语言生成
  ↓
SQLite / PostgreSQL（会话、分析版本、策略元数据、订单、授权、审计日志）
```

### 7.2 关键模块职责

| 模块 | 职责 |
|---|---|
| 策略商店服务 | 管理策略上下架、定价、分类、搜索、详情展示 |
| 授权服务 | 校验用户是否拥有某策略的使用权（免费/购买/订阅） |
| 策略表现跟踪服务 | 每日运行策略，记录信号和结果，生成最近三个月表现数据 |
| 对话引擎 | 维护会话上下文，理解用户意图，管理多轮交互 |
| 信息抽取引擎 | 根据当前策略的信息依赖声明，从对话和附件中提取字段 |
| 数据能力平台 | 提供量价数据、事件因子、指标计算、数据质量校验 |
| 策略注册表 | 管理策略生命周期：发现、注册、版本控制、启用/停用 |
| 策略运行时 | 执行策略插件，传入标准化输入快照，返回结构化结果 |
| 风险与约束层 | 校验策略运行的合规性、数据完整性、风险边界 |
| 结果渲染器 | 将策略结果转换为自然语言、可视化图表、结论卡片 |
| 审计存储 | 保存每次分析的输入快照、策略版本、输出结果、证据链 |

### 7.3 数据流

```text
1. 用户进入策略商店浏览策略
2. 系统展示策略元数据和最近三个月表现
3. 用户选择购买策略
4. 系统记录授权状态
5. 用户进入对话，选择已授权策略
6. 用户发起分析请求（自然语言 + 可选附件）
7. 系统识别用户意图：策略、标的、时间范围
8. 系统检查用户是否有当前策略的使用权限
9. 系统加载当前策略的信息依赖声明
10. 系统从对话历史、当前消息、附件中抽取已提供的信息
11. 系统检查缺失信息，判断哪些是用户必须补充的
12. 如信息不足，系统向用户提出澄清问题
13. 信息完整后，系统从内部数据平台获取策略所需数据
14. 运行策略，生成预测分析结果
15. 渲染结果：自然语言总结 + 可视化 + 策略链路 + 审计信息
16. 用户可追问、修正或发起新分析
```

2. 进入对话界面。
3. 用户输入："分析一下螺纹钢接下来一周的走势。"

1. 用户打开历史会话列表。
2. 选择一个正在关注的标的会话。
3. 输入新问题或上传截图。

1. 用户在会话中表达"换用突破跟随策略看看"。
2. 系统检查用户是否拥有该策略权限。
3. 系统确认切换意图。
4. 系统复用已确认的标的和用户信息。
5. 使用新策略重新运行。
6. 展示新旧策略结论对比（可选）。

## 9. 策略系统

### 9.1 策略定义

策略是磐石交易AI的核心商品和分析单元。每个策略包含：

- **策略元数据**：ID、名称、版本、状态、适用市场、适用周期、简介、价格。
- **信息依赖声明**：策略运行所需的输入字段、字段类型、是否必填、获取方式。
- **数据需求声明**：策略运行所需的数据类型、时间范围、指标。
- **策略逻辑**：基于输入快照和数据运行分析，输出结构化结果。
- **结果Schema**：预测方向、概率、关键价位、触发条件、失效条件、风险提示等。

### 9.2 策略接口

所有策略必须实现统一接口：

```python
class StrategyPlugin(Protocol):
    manifest: StrategyManifest

    def required_facts(self, context: dict) -> list[FactRequirement]:
        """声明当前策略需要哪些事实。"""
        ...

    def required_data(self, context: dict) -> list[DataRequirement]:
        """声明当前策略需要哪些系统数据。"""
        ...

    def evaluate(self, snapshot: StrategyInputSnapshot) -> StrategyRun:
        """运行策略，返回结构化结果。"""
        ...

    def track_performance(
        self,
        start_date: date,
        end_date: date,
        market_data: MarketDataBundle,
    ) -> PerformanceTrack:
        """生成指定时间段的策略表现跟踪数据。"""
        ...
```

```json
  "invalidation_conditions": [
    "价格跌破3550支撑",
    "放量跌破20日均线"
  ],
  "risk_note": "若持仓方向与策略方向相反，建议控制风险。",
  "milestones": [...],
  "evidence_refs": [...]
}
```

### 9.6 策略注册与扩展

- 新策略通过 `src/trading_agent/strategies/` 目录下的 Python 模块实现。
- 在 `configured_strategy_registry()` 中手动注册。
- 策略状态：`stable`（可上架）、`test`（仅内部/白名单）、`disabled`（不上架）。
- 已生成的分析永久绑定原策略版本，切换策略生成新版本。

## 10. 策略近期表现

### 10.1 目的

- 向用户展示策略在最近三个月的实际运行情况。
- 帮助用户直观判断策略是否值得购买。
- 作为策略上架的必要条件。

### 10.2 展示内容

策略详情页的"最近三个月表现"区域展示：

| 内容 | 说明 |
|---|---|
| 整体涨跌 | 最近三个月累计涨跌幅度 |
| 信号次数 | 最近三个月共产生多少次信号 |
| 盈利次数 | 信号中盈利的次数 |
| 亏损次数 | 信号中亏损的次数 |
| 胜率 | 盈利次数 / 总信号次数 |
| 最大回撤 | 期间从高点到低点的最大亏损 |
| 收益曲线 | 资金随时间变化的曲线 |
| 信号记录 | 每次信号的时间、标的、方向、结果 |

### 10.3 页面示例

```text
┌─────────────────────────────────────────────────────────────┐
│ 最近三个月表现（2025-05-12 至 2025-08-12）                   │
│                                                             │
│ 整体涨跌  +12.5%        信号次数  24次                       │
│ 盈利次数  15次          亏损次数  9次                        │
│ 胜率      62.5%         最大回撤  -5.1%                     │
│                                                             │
│ [收益曲线图]                                                │
│                                                             │
│ 最近信号记录                                                 │
│ 日期         标的      方向      结果                        │
│ 2025-08-11   RB2510   做多      盈利 +1.2%                  │
│ 2025-08-08   RB2510   观望      无                          │
│ 2025-08-05   RB2510   做空      亏损 -0.8%                  │
│ ...                                                         │
└─────────────────────────────────────────────────────────────┘
```

### 10.4 通俗化表达

避免使用"回测""模拟"等专业词汇，采用用户易懂的说法：

- "最近三个月表现"
- "这个策略最近三个月涨了/跌了多少"
- "最近给出了多少次信号"
- "这些信号中对了多少次"
- "最大一次亏了多少"

### 10.5 数据要求

- 每个上架策略必须提供至少最近三个月的连续表现数据。
- 表现数据每日更新。
- 必须说明统计起始日期和结束日期。
- 信号结果基于策略逻辑和公开行情计算，不虚构。
- 表现数据必须可审计、可复现。

### 10.6 注意事项提示

页面必须展示风险提示：

> 以上表现基于历史行情计算，不代表未来收益。策略信号可能因市场变化而失效。

## 11. 商业化设计

### 11.1 商业模式

- **免费策略**：平台提供的基础策略，吸引用户使用。
- **付费策略**：用户单次购买或订阅使用。
- **策略分成**：策略开发者获得销售分成（未来）。

### 11.2 定价模式

| 模式 | 说明 | 适用场景 |
|---|---|---|
| 免费 | 无需付费，永久使用 | 基础策略、引流策略 |
| 单次购买 | 一次性付费，永久使用当前大版本 | 成熟稳定策略 |
| 月度订阅 | 按月付费，订阅期内可用 | 持续更新策略 |
| 年度订阅 | 按年付费，通常有折扣 | 长期跟踪策略 |

### 11.3 授权模型

- 用户购买/订阅策略后，授权记录保存到用户账号。
- 订阅到期后，策略从"可用"变为"已过期"。
- 已过期策略：
  - 不能新建分析；
  - 可以查看历史分析；
  - 可以查看策略商店详情；
  - 可以续费。
- 单次购买策略：永久授权当前版本，大版本升级可设置补差价。

### 11.4 购买流程

1. 用户在策略详情页选择购买/订阅方案。
2. 系统展示价格、权益、风险提示。
3. 用户确认并选择支付方式。
4. 调用支付接口完成支付。
5. 支付成功后立即开通策略权限。
6. 发送购买确认通知。

### 11.5 退款与售后

- 策略购买后是否支持退款由平台规则决定。
- 可设置"7天无理由退款"或"未使用可退款"。
- 退款后收回策略使用权限。

## 12. 非功能性需求

### 12.1 性能

- 策略商店列表加载时间不超过 1 秒。
- 策略详情页加载时间不超过 2 秒。
- 最近三个月表现数据预计算，页面展示不超过 1 秒。
- 普通分析请求响应时间不超过 10 秒（不含数据获取耗时）。
- 复杂策略分析响应时间不超过 30 秒。
- 对话消息渲染延迟不超过 200ms。

### 12.2 可用性

- 系统可用性目标 99.9%。
- 数据服务异常时，系统应优雅降级并告知用户。

### 12.3 安全

- 用户密码使用 scrypt 哈希存储。
- 会话 Cookie 为 HttpOnly，12 小时绝对有效期。
- API Token 不下发到浏览器。
- 原图存储在私有目录，访问受鉴权控制。
- 支付信息不存储在平台，使用第三方支付服务。

### 12.4 可扩展性

- 新策略接入不修改核心会话、数据、风控、前端组件。
- 数据能力和策略运行时解耦，可独立扩展。
- 商业化模块与策略运行时解耦，支持多种定价模式。

### 12.5 可审计

- 每次分析保存完整输入快照、策略版本、输出结果、证据链。
- 所有用户确认事实标注来源和置信度。
- 支持分析版本回溯和差异对比。
- 所有购买记录、授权变更保存审计日志。

## 13. 风险与安全

### 13.1 合规声明

- 磐石交易AI 仅提供分析和决策支持，不构成投资建议。
- 当前版本禁止连接实盘交易网关。
- 用户需自行承担交易风险。
- 策略最近三个月表现不代表未来收益。

### 13.2 模型安全

- 大模型不独立生成交易动作。
- 所有结论必须由确定性策略产生。
- 模型解释基于策略结果，不编造依据。

### 13.3 数据安全

- 用户持仓等敏感信息仅用于当前分析，不用于模型训练。
- 截图原图仅保存在用户私有存储空间。

### 13.4 商业风险提示

- 策略商店中的最近三个月表现基于历史行情计算，不代表未来真实收益。
- 策略开发者（未来）需通过平台审核才能上架。
- 平台对策略效果进行披露，但不保证策略未来表现。
